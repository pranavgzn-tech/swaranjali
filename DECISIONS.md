# DECISIONS.md

Every judgement call, with a one-line reason. Newest phase at the bottom.

## Phase 0

**Development happens on `claude/swaranjali-spec-setup-gfp5y1`, not `main`.**
`PROMPT.md` asks for commits straight to `main`, but this session was opened with a
standing instruction not to push elsewhere without explicit permission. The Pages workflow
therefore deploys from that branch as well as `main`, so the testable URL is unaffected.
Say the word and it moves to `main`.

**Fixed a spec inconsistency: F2–C6 is 44 keys, not 42.** Doc 02 says the range "spans F2 to
C6 (42 semitones), matching a 42-key harmonium". F2 to C6 inclusive is 43 semitones and 44
keys; 42 keys from F2 would end at A♯5. `RANGE` in `config/layout.ts` implements the named
endpoints F2–C6, because those are what the user will see on the octave shift. Flagging
rather than silently picking — tell me if you want the range trimmed to end at A♯5 instead.

**Portrait on a tablet is decided by width, at 700 pt.** Doc 02 wants the rotate message on
iPad portrait; doc 11 wants companion mode on iPhone portrait; doc 11's `sizeClass()`
returns `compact-portrait` for both and we may not read the user agent. An iPad Air is
820 pt wide in portrait, the largest iPhone is 430, and an iPad Split View column is
narrower still and genuinely wants companion mode — so 700 pt separates them cleanly.

**The service worker does not call `skipWaiting()` on install.** Doc 12's code sketch shows
it, but the same doc's "Updates" section says a new build must wait for the user to tap
restart and must never swap itself out mid-phrase. The sketch is labelled "shape only", so
the prose wins: the worker waits for a `skip-waiting` message from the settings panel.

**Fader positions are centred by cap edge, not by centre.** Doc 02 gives ten faders at an
88 pt pitch in an 880 pt mixer — exactly 880 — plus a 14 pt master gap and 62 pt caps, which
overflows the band by 38 pt. `faderCentres()` centres the outermost cap edges instead, which
keeps the pitch and the gap and leaves 6 pt of margin at each end. Caught by
`npm run check-layout`.

**`npm run check-layout` runs on every build.** CLAUDE.md's definition of done requires
reasoning through three viewports and confirming nothing overflows. This asserts it
arithmetically at ten viewports — including both Dynamic Island rotations and Split View —
using the same functions the app uses at runtime, so a constant that stops fitting fails the
build rather than surfacing on the device. It caught the fader overflow above.

**Icons and launch screens are generated by a hand-written PNG encoder.** Docs 06 and 12
want them generated at build time from one source, and Node has no image encoder. Rather
than add `sharp`, `scripts/png.ts` writes the PNG directly (~110 lines, `node:zlib` for the
deflate) and `scripts/gen-assets.ts` rasterises the mark by signed distance. Runtime
dependencies stay at zero and dev dependencies stay at three.

**The mark is a bowl holding a single note.** Nothing in the spec describes the icon. A
cupped bowl with one note held above it reads as *swara* and *anjali* — the offering the app
is named for — and it is simple enough to stay legible at 180 px and to draw as maths. The
same form appears as inline SVG on the "Tap to begin" screen.

**Dev dependencies: `vite`, `typescript`, `@types/node`.** Runtime dependencies: none, and
none are planned. `@types/node` is types-only and exists so the build scripts are
typechecked rather than trusted.

**Build scripts run through Node's type stripping** (`node --experimental-strip-types`),
which needs no build step of its own. The service worker is compiled by `tsc` alone, with
no bundler, so `dist/sw.js` stays a classic script — module service workers are not worth
the risk to the offline guarantee.

**`viewport` measures lazily, not at module load.** `ui/size-class.ts` is imported by the
build-time layout check, which has no DOM; the first real measurement happens in
`watchViewport()`, synchronously, before anything subscribes.

**Fonts are still system fallbacks.** `tokens.css` names `Swaranjali Serif` and
`Swaranjali Sans` with `ui-serif` / `ui-sans-serif` behind them. The self-hosted WOFF2 subset
faces land in Phase 1 alongside the key labels, which is the first thing that depends on
them; the licence goes in this file when they do.
